# Data Model: Verifiable Cited Answer

**Date**: 2026-08-04

## Conventions

- Primary keys are UUIDv7 values generated by the backend unless a natural immutable identifier is
  explicitly listed.
- Timestamps are timezone-aware UTC.
- Public IDs are opaque; database sequence numbers are never exposed.
- Corpus records are immutable or append-only. Interaction content expires after 30 days.
- Public/API roles have no direct table access. Backend, worker, migration, and read-only operations
  use separate least-privilege database roles.
- Enumerations below are database checks or generated application enums; free-form status strings
  are not allowed.

## Corpus Domain

| `created_at` | timestamptz | Required |

### `sources`

A logical documentation page, changelog, or release that can have multiple captured versions.

| Field | Type | Rules |
|-------|------|-------|

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key; expires with run |
| `answer_run_id` | UUID | FK; required |

### `usage_events`

Minimal append-only quota ledger.

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key |
| `visitor_key_hash` | char(64) | HMAC only |
| `answer_run_id` | UUID | Unique FK for accepted questions |
| `accepted_at` | timestamptz | Required; indexed with visitor hash |
| `expires_at` | timestamptz | At least 30 days; no question content |

Quota reservation obtains a transaction-level advisory lock for `visitor_key_hash`, counts events
newer than `now() - interval '24 hours'`, and inserts the event and run atomically when count < 10.

| Field | Type | Rules |

| `accepted_count` | bigint | Non-negative |

| `abstained_count` | bigint | Non-negative |
| `error_count` | bigint | Non-negative |
| `quota_denied_count` | bigint | Non-negative |
| `useful_count` | bigint | Non-negative |
| `citation_count` | bigint | Non-negative |
| `input_tokens` | bigint | Non-negative |

## State Transitions

### Answer run

```text
accepted
  -> retrieving
      -> abstained             # insufficient evidence
      -> composing
          -> verifying
              -> completed     # verified answer/partial answer persisted
              -> abstained     # citation gate failed

Any active state -> cancelled  # client disconnect/cancel request
Any active state -> failed     # controlled terminal error
```

Terminal states: `completed`, `abstained`, `cancelled`, `failed`. A terminal run cannot return to an
active state. Draft model text is not persisted as a user-visible answer.

### Ingestion run

```text
queued -> running -> succeeded
                  -> partial
                  -> failed -> queued       # bounded retry
                            -> dead_letter   # retry budget exhausted
```

### Source version

```text
staged -> active -> superseded
       -> rejected
```

Promotion and superseding occur in one transaction. Rejected versions never become evidence.

## Retention Process

1. Select expired runs in bounded batches with `FOR UPDATE SKIP LOCKED`.
2. Upsert aggregate values into `daily_metrics` using an idempotent retention-batch key.
3. Delete feedback, claim-evidence links, claims, run evidence, and content-bearing diagnostics.
4. Delete or tombstone the answer run so no question/answer content remains.
5. Delete expired usage events after they are outside every quota and audit requirement.
6. Emit content-free counts and failures; retry without duplicating aggregate metrics.

Database integration tests MUST prove deletion within the required extra 24 hours and preservation
of only the allowed aggregate dimensions.
